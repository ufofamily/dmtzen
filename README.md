# BARDO — GitHub Pages edition

Самостоятельная статическая версия: **114 сцен, 13 переходов**, DMT-эффекты,
музыкальная динамика, аудиомаршрутизация и чистый полноэкранный просмотр.
**Нет MP4-экспорта, FFmpeg, серверного API, аккаунтов и загрузки музыки в сеть.**
Для посетителя нужен современный браузер с WebGL2, Web Audio и Web Workers.
На телефонах поддержка полного экрана зависит от браузера.

## Публикация на GitHub Pages

### Вариант A — исходники и GitHub Actions

1. Создайте репозиторий и поместите **содержимое этой папки** в его корень.
   Нужны `src`, `public`, `.github`, `package.json`, `package-lock.json`,
   `tsconfig.json`, `vite.config.mjs`, `index.html`. Не загружайте `node_modules`.
2. В Settings → Pages → Build and deployment → Source выберите **GitHub Actions**.
3. Отправьте изменения в `main` или запустите workflow вручную в Actions.
   Если основная ветка называется иначе, измените `branches` в workflow.
4. Дождитесь задания Deploy. Адрес опубликованного сайта появится в Pages.

Workflow `.github/workflows/pages.yml` устанавливает зависимости через `npm ci`,
проверяет TypeScript, собирает `dist` и публикует только этот каталог.
Для репозитория, где BARDO лежит в подпапке, нужно изменить рабочую папку и пути
workflow; предложенная конфигурация рассчитана на корень отдельного репозитория.

### Вариант B — уже собранный сайт

Содержимое **dist** (или архива `bardo-pages-site.zip`, поставляемого рядом)
можно разместить в корне отдельной ветки или папке `docs`, выбрав в Pages
**Deploy from a branch**. Загружайте именно содержимое dist, не папку-обёртку.
В сборке есть `.nojekyll`. Относительные пути `base: './'` поддерживают как
корневой сайт, так и `https://имя.github.io/репозиторий/`.

Публикация подготовлена, но сайт ещё не размещён в вашем GitHub: репозиторий
и доступ к аккаунту не предоставлялись. Официальные инструкции:
[GitHub Pages workflows](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages),
[Vite deployment](https://vite.dev/guide/static-deploy).

## Локальный запуск и сборка

Windows: **start.cmd** проверяет Node.js, при необходимости вызывает установщик
локального Node.js 22 LTS с проверкой SHA-256 и устанавливает библиотеки через npm.
Первый запуск требует интернета; администратор не нужен. FFmpeg и Chromium
не устанавливаются. Студия открывается на порту **5177**.

На любой системе с Node.js 22+:

```sh
npm ci
npm run dev
npm run build
npm run preview
```

Браузер запускает собранный сайт по HTTP(S), не через `file://` двойным щелчком
по index.html. Самому GitHub Pages не нужен постоянно работающий Node.js.

## Музыка и динамика

Выберите локальный трек. Web Audio декодирует его с частотой анализа 20480 Гц,
а Worker выполняет FFT и формирует 20 отсчётов в секунду (RMS, бас, высокие).
Аудио не отправляется в сеть. Воспроизведение использует оригинальный файл;
анализ управляет только визуализацией. После перезагрузки музыку нужно выбрать
снова. Save/Open settings сохраняют JSON-проект, а Save/Load features — признаки.
Поддерживаемые аудиоформаты зависят от браузера.

Встроенный анализ ограничен **64 MiB и 20 минутами**, поскольку декодирование
требует памяти. Для длинной записи можно импортировать заранее рассчитанные
признаки из локальной версии BARDO; плеер продолжает работать без этого анализа.
Анализ можно отменить. Уже начатое браузерное декодирование прервётся логически:
его результат будет отброшен, но браузер может закончить саму операцию.
До успешного анализа/импорта признаки нулевые — это не демо-реакция на музыку.

Режимы динамики: выключена, медленное дыхание, следование энергии, нарастание /
разрядка. Регулируются сила, минимум, максимум и время отклика. Движение
интегрируется по музыкальной энергии без зависимости от предыдущего кадра.
Это не обнаружение BPM; расписание сцен не переставляется по ударам.
Отдельная аудиоматрица направляет выбранную полосу на семь получателей.

114 миров включают 70 новых композиций: 14 геометрических семейств с пятью
раскладками. Короткие треки показывают подмножество сцен. Все сцены также
доступны вручную через поиск. Образцы — художественные интерпретации,
а не точные реконструкции буддийских объектов.

F, двойной щелчок или кнопка — полный экран; Esc — выход. Надписей на изображении
нет. Разрешение предпросмотра ограничено 1440×900, частота — до 30 кадров/с.
Reduced intensity ограничивает эффекты, но не гарантирует безопасность при
фоточувствительности. DMT — художественное название, не медицинская модель.

## Проверка

Сборка проверена как статические файлы в подпапке `/repository/`: загрузка
Worker, FFT синтетического аудио, воспроизведение, перемотка, сохранение
настроек, полноэкранный режим, мобильная раскладка и отсутствие запросов к API.
Тесты полной поставки находятся в соседней `bardo-v3/tests/pages.test.mjs`.
Сам запуск workflow на GitHub и реальные мобильные устройства не проверялись.
